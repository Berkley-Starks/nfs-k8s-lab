# Small-lab storage baseline, 2026-10-18

The released NFS CSI driver and a source build passed the same two-node storage
checks. The released driver is restored as the default baseline. Both nodes are
Ready, and the test namespaces, PVCs, PVs, StorageClasses, and volume directories
have been removed.

The source image uses the released runtime with its driver binary replaced.
It omits upstream release-version linker metadata. The server build, live
inventory, credentials, and raw logs are recorded privately.

## Results

The released driver ran first, followed by the source build on the same cluster
and export. Each run used a new namespace, StorageClass, and PVC.

| Check | Released driver | Source build |
| --- | --- | --- |
| Dynamic provisioning binds the RWX PVC | Pass | Pass |
| Each node writes 1 MiB; the other verifies its SHA-256 hash | Pass | Pass |
| Both files survive writer-pod recreation | Pass | Pass |
| Deliberate corruption fails the checksum check; restoration passes | Pass | Pass |
| Namespace, PVC, PV, and StorageClass are deleted | Pass | Pass |
| Volume directory exists while bound and disappears after cleanup | Pass | Pass |

The directory check used the PV's `subdir` attribute and a separate, verified
client mount of the export. A forced metadata check confirmed the directory's
removal, and the export's volume-directory list returned to its starting state.

After the comparison, the released driver was restored with reset chart values.
The controller and both node plugins became Ready with the expected release
image digest. No test PVs, PVCs, namespaces, or StorageClasses remained. The
source image is still loaded on both nodes for later comparisons.
